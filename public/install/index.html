Stays in your code
That looks like a private key or seed phrase. Never paste those anywhere — use the public key (zpub) or a receive address.
How this works. Customers pay your address from any wallet they own. Your listener watches the chain, confirms the transfer, and POSTs a signed webhook to your server. ZettaPay never holds funds and takes no per-transaction fee. If your EVM wallet can export an xpub, the listener can also derive one Base address per invoice (--xpub-evm). Read the listener README →

Verify the install

              
Five checks, all against your own machine. None require an account.

            

            
              
              HMAC-SHA256
            
          


          
          

            
CLI · built into the listener

            

              
# validate the .env without starting anything
zettapay-listener verify-config
# probe a running listener (exit code 0 = healthy)
zettapay-listener healthcheck

            

          


          
Manual checklist · works today


          

            
1

              
Listener is up

              

              
curl http://localhost:8787/health

              Should return "ok": true with ws_connected and the latest block height.

            

            
2

              
Env vars are set in your app

              
MERCHANT_WEBHOOK_SECRET and ZETTAPAY_API_KEY must match the listener’s .env. Restart your dev server after editing.

            

            
3

              
An invoice can be created

              
Run the generated invoice call. The response should carry an invoice_id, a receive_address and a qr_uri. A 401 means the API key does not match.

            

            
4

              
Webhook endpoint reachable

              
The URL you passed to --webhook-url must be HTTPS and reachable from the machine running the listener (plain http://localhost is accepted for development).

            

            
5

              
Signature verification works

              
POST any body to your webhook with a wrong X-ZettaPay-Signature — your handler should reject it with 401. That’s the HMAC doing its job. Your webhook secret never leaves your servers.

            

          


          

            

              ★
              

                
Ready for a first payment.

                
Create a small invoice and pay it from any wallet. Once the transfer confirms on-chain, your listener POSTs invoice.confirmed to your webhook and retries until your server answers 2xx.
